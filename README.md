# GSB Bugfix Task
## 题面
工坊排队做装备的功能上线后，客服工单翻了三倍。玩家排了五件，取消第三件，前两件的材料退了，第三件的材料也退了，可成品还挂在队列里等着领；离线八小时回来只完成两件，剩下几件显示的剩余时间比下线时还长；两台设备同时点领取，背包里多出一件同样的装备；制作到一半把对应职业洗掉，成品做出来了却不能装备，材料也不退；工坊耐久已经归零还在接单，出来的品质按满耐久算；队列满了界面仍提示排队成功，材料扣了但根本没进队列；玩家手动调整队列顺序，正在做的那件被重置，材料又扣了一遍；维护时正在制作，重启后进度归零，之前投的材料也查不到；同账号两个角色共用工坊，A角色的订单跑到B角色界面上；限时活动配方过期后，已排队的订单失败，扣掉的材料按活动折扣价退，少了三成；跨天维护后离线收益按分钟补发，补出来的成品数量跟界面显示的差好几件。crafting_queue_station.py 的 CraftingQueueStation 要管入队、取消、领取、按秒推进和重启恢复。取消订单只能退还没消耗的那部分材料，已经投进去的要按配方表精确退回，少退多退都算事故，退款记录要能和订单逐条对上；领取和调整队列顺序都按订单编号加锁，同一订单并发领两次只成功一次，第二次返回 already_claimed，正在制作的订单不能被重排或二次扣料；重启后从制作快照恢复剩余秒数和已投材料，不能重扣也不能白送；入队时的配方版本要跟着订单走，配方改价后老订单仍按原版本结算；工坊耐久为零时新订单要直接拒绝，抛 StationBrokenError，别让玩家等半小时才发现。工坊这套账我拿三个角色倒过一遍，先让材料、队列和成品能对上，再排后面的活动。

```bash
python -m pytest tests -q
```
