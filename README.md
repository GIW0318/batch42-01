# GSB Bugfix Task
## 题面
回合制宠物对战的赛季刚开，论坛就被结算问题刷屏。双方最后一击同时打死对面的宠物，系统判平局，可两边都扣了分；换宠和技能在同一回合提交，速度快的先换，结果技能打在刚下场的那只身上；手机网络重试把同一回合的指令提交了两次，对面的宠物连着动了两回合；掉线重连后看到的血量和能量还是上一回合的，继续操作全被服务器打回；加速buff到底在回合开始还是结束结算没有准数，同样的阵容打两局结果相反；隐身到期的回合发动攻击，有时候打空有时候命中；对手拔线后托管AI一直放同一个技能，回合数超过上限也不判结束；观战端显示的回合总比战斗端慢一，直播弹幕全在问谁赢了；回放文件换一个客户端版本打开，随机种子对不上，整场过程完全变样；战斗服重启后进行中的对局全部消失，在线玩家统一判负；客服想按回合日志复盘，发现只留下最终血量，出手顺序和随机种子都没记。pet_duel_turn_arbiter.py 的 PetDuelTurnArbiter 负责收指令、结算回合、断线接管和快照。同一回合同一玩家重复提交只认第一条，第二条返回 turn_already_committed；结算顺序必须按速度、技能优先级和固定随机序列排，同一份指令重放一百次，不管三十帧还是六十帧结果都要一致；托管AI出的指令要和玩家指令走同一套冷却校验，不能绕过；服务重启后从最近一个回合快照恢复，双方血量、能量、技能冷却和buff层数都要对上，不能借机判负；投降和最后一击撞在同一回合时只能出一个结果，积分也只变一次。我还希望回合快照能按对局和回合号回查，客服复核时不用把整场重跑一遍。我这边存了二十场对局录像，先把回合结算和断线恢复捋顺，后面的平衡性再谈。

## 运行方式
```bash
python -m pytest tests -q
```
