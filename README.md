# GSB Bugfix Task
## 题面
我们的节奏游戏接了外部 MIDI 设备以后，音符开始漂。外部时钟抖动大的时候，软件时钟还在按自己的节拍走，note-on 提前十几毫秒触发，鼓点和画面差出一整帧，全抢拍；停止播放以后还有几个 note-on 挂着，合成器一直响；中途改速度，已经排队的事件还按旧速度发，越到后面偏得越多，最后差出一拍；循环回到起点时拍号没有重置，第二遍的重音全错位；USB 设备拔掉再插上，端口编号变了，系统还认着旧名称，事件发到不存在的输出；两个输出端口同时发声，时钟慢慢漂开，一个比另一个晚半拍，合奏像卡农；暂停恢复以后时间戳跳变，排队的音符一次性全冲出来；同一个 note-on 被重复发送，听起来像双击；系统休眠唤醒后时钟基准错了，所有事件整体延后，重启才恢复；大合奏时事件堆积在缓冲区，最后一帧才批量发出；量化把弱起音符吸到下一拍，节奏完全变了；关闭工程时没有发 all-notes-off，下次打开还有残响，硬件上留着一排长音。midi_clock_conductor.py 的 MidiConductor 要把时钟、事件队列和输出端口分开，所有事件带采样级时间戳；事件按时间戳排序发送，跨端口也按同一时间基对齐，同一时间戳按提交顺序，不能批量乱序；note-on 和 note-off 要成对出现，同音高重叠要单独计数，停止、暂停和关闭时强制补发所有未配对音符；速度变化只影响之后的事件，设备热插拔后按端口名称重新绑定，绑定失败抛 MidiDeviceError，循环回到起点时时间戳继续单调递增。录音师把两台合成器的录音对了一遍。三台 MIDI 设备我连着跑了两个晚上，问题一个都没少。

