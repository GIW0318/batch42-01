# GSB Bugfix Task
## 题面
VoIP 网关升级密钥轮换以后，客服坐席反馈通话里一直有爆音，严重的直接单通。新旧两代密钥在切换窗口里混着用；乱序包到达时包序号推算错了，解密出来全是噪声；切换同步源时重放窗口没重置，新流的包被当成重放丢掉；同一个同步源从两个地址同时进来，包被混在一起解密；没带密钥标识的包选不到密钥，直接被丢；媒体进程重启后密钥没从安全存储恢复，通话中断；密钥到了有效期没有强制切换，一把密钥用到挂断；控制通道和媒体通道的序号分开算，统计对不上；丢包重传的包用上一代密钥加密，接收端全丢；两个线程同时触发密钥切换，状态互相覆盖；超长通话包序号回绕，之后所有包解不开；日志把密钥材料打了出来；接收端按包序号直接找密钥，没有先看同步源，两个会议混流时解错；密钥切换和包处理共用一把锁，控制线程一阻塞媒体线程就卡住；切换失败没有留下原因，审计只有成功记录；清理旧密钥时把仍被在途包引用的那一代删掉，重传包全部解不开。srtp_key_epoch.py 的 SrtpEpochKeeper 要按同步源和密钥代次维护两套索引。硬门禁：新密钥确认可用之前旧密钥不能停用；同一同步源并发只允许一个地址；重启后密钥和包序号必须从落盘状态恢复；重放包必须丢弃并单独计数。test_srtp_key_epoch.py 的十五条用例在实验室复现了三轮，每轮都是全红。

## 运行方式
```bash
python -m pytest tests -q
```
