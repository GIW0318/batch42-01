# GSB Bugfix Task
## 题面
卡牌对战的新扩展包上线后，结算顺序成了玄学。玩家同时打出两张法术，费用只扣了第一张，第二张白嫖，回放里也查不到扣费记录；连锁触发按卡牌编号的字典序结算，而不是按打出顺序，伤害全打到了错误的随从上；反制牌结算完，被反制的那张牌效果还是执行了，双方各掉一次血；洗牌用的是客户端时间做种子，重连后手牌顺序和对手看到的完全不一样；回合超时自动过牌，把玩家刚打出、还在结算队列里的牌又打了一次；墓地计数在牌被除外后不回退，复活类卡牌因此多召了一个；观战端收到的结算顺序和选手端不同，弹幕一直在问谁赢了；复制手牌时复制了对象引用，改一张另一张跟着变；牌库为空时抽牌直接空指针崩溃，客户端只显示正在同步；断线重连丢掉结算队列的中间状态，回来时场上多了一个不该存在的随从；一张牌把英雄打到零血，后续的治疗和护盾仍然生效；同一张牌在一回合内被减费两次，第二次减费叠到了负数。card_play_resolver.py 的 PlayResolver 要维护一条只追加的结算日志，每条命令带玩家编号和递增序号，重复命令按序号去重；随机数用服务端种子，洗牌、发现和随机目标共用一条序列，并在重连快照里带上，保证两端洗牌一致；命令要么整条生效要么完全不生效，费用、手牌、场面和墓地一起提交；非法目标、费用不足和已结束的对局分别抛 CardRuleError 的不同错误码。测试组已经把十二种复现录成视频。这十二种情况我攒了两周，测试里一条都没过去。

## 运行方式
```bash
python -m pytest tests -q
```
