# GSB Bugfix Task
## 题面
双因素后台的备用码被人撞库，两个高权限账号在一夜之间被接管。备用码在库里是明文，读一份备份就能直接登录；比较用了普通的字符串相等，响应时间能透出前几位；一个码用过之后没有作废，同一张纸可以反复用；生成时用的随机源是时间种子，相邻账号的码能推算出来；页面展示后还没等用户确认保存就标记成已发放，关掉页面就再也找不回；重新生成时没有清掉旧码，几年前打印的纸仍然有效；备用码和动态口令共用失败计数，一边输错把另一边也锁了；输入时大小写和连字符的处理不一致，用户照着抄也进不去；两个请求同时兑换同一个码，两个会话都拿到了登录态；码空间快用完时没有任何告警；账号被停用后备用码还能兑换；码的位数和字符集在生成端与校验端不一致，十位的码在页面上只能输入八位。recovery_code_curator.py 的 RecoveryCodeCurator 要只保存带盐的摘要并用常量时间比较，兑换按码和账号做幂等且成功后立即失效，重新生成要整批替换旧码，账号状态在兑换前复查，失败响应统一，兑换记录落盘并在重启后保持，码的消费记录按账号和时间建立索引。test_recovery_code_curator.py 的十五个用例从昨天挂到现在，没有起色。

## 运行方式
```bash
python -m pytest tests -q
```
