# GSB Bugfix Task
## 题面
物联网设备改走 EST 注册后，证书签发开始出乱子，有的设备拿到两张证书，有的拿到一张能签子证书的怪东西。cacerts 接口返回的 CA 链没有验签，设备把一条伪造链装进了信任库；CSR 里的 challengePassword 没有和一次性口令比对，任何设备都能申请；续期请求用旧证书认证，但没有核对新旧证书的 Subject 是否一致，别的设备可以顶替；同一台设备的两个注册请求并发到达，签出了两张序列号不同的证书；服务端返回 202 和 retry-after 时客户端当成失败直接放弃；PKCS#7 封装的响应不验签名者，中间人可以替换证书；证书模板忽略了 CSR 里的 keyUsage，签出来的证书带上了签子证书的能力；注册额度按来源地址统计，NAT 后面的设备互相挤占；HTTP 认证只用了 Basic，没有强制客户端证书；已经被吊销的设备仍然可以通过续期拿新证书；服务端重启后未完成的注册任务丢失，设备一直停在 pending。est_enrollment_warden.py 的 EstEnrollmentWarden 要让注册任务按设备幂等，CSR、设备身份和签发结果三者对得上，续期必须比对 Subject 和密钥，吊销状态在签发前复查，202 的重试语义要正确处理，重启后从持久队列恢复未完成任务。test_est_enrollment_warden.py 十五条用例在预发环境连跑两轮，两轮皆红。

## 运行方式
```bash
python -m pytest tests -q
```
