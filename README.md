# GSB Bugfix Task
## 题面
载具改装系统上线后，战局里开始出现各种怪东西。把坦克炮塔装到摩托车上，客户端不拦，进战局模型直接炸开；两辆车同时拆同一个发动机，拆下来两份，原车还能正常开；保险理赔后车恢复了，改装件没回来，理赔记录里只写了车辆ID，客服补发又复制出一套；车库满了还能买新车，旧车被静默覆盖，覆盖前也没有任何确认；蓝图版本更新后旧车悬挂参数变成零，开出去就翻车；车辆被击毁后残骸还能被队友开走，战斗结算多算一份击杀；跨车库转移时正在改装，转移后进度丢失，材料也不退；同一个改装槽并发装两件，界面显示一件，属性叠了两件；赛季清零把限定涂装也清了，客服只能按截图手工补，申诉只补车不补涂装；车库里车辆顺序每次登录都变，预设方案对不上车；同一辆车的两个预设方案同时应用，最终属性取了两套的并集；车辆在战局里被击毁，回车库后保险状态还是已投保，理赔按钮却灰了。vehicle_assembly_garage.py 的 VehicleAssemblyGarage 管装配、拆解、转移、理赔和恢复。槽位兼容必须在服务端按车辆型号和蓝图版本两项一起校验，不兼容抛 SlotIncompatibleError 并保持原车不变；拆装要原子，同一部件只能存在于车上或仓库里，并发拆装只成功一次；击毁结算按对局和车辆幂等，重复上报不重复算击杀和理赔；重启后未完成的转移或改装从日志续做，不能既扣了材料又没装上，也不能把同一部件记在两辆车上。改装属性以最终装配结果为准，战力计算和战斗属性都读同一份装配快照，不能各自缓存。车库和战局两头都在丢东西，先把拆装、理赔和转移做成一本账。

## 运行方式
```bash
python -m pytest tests -q
```
