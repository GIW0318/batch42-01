# GSB Bugfix Task
## 题面
交易行最近天天有人来申诉，说面对面交易的账对不上。两个人都点了锁定，其中一个人又偷偷把金币从十万改成一百万，另一边界面没刷新，成交后买家只付了十万；交易进行到一半把武器强化了，对方收到的是强化后的属性，可强化材料和原武器都还在卖家包里；背包只剩一格时成交，三件装备只进去一件，另外两件掉在地上被路过的人捡走；金币输入超过上限直接变成负数，卖家反而倒欠系统钱；网络一抖，确认包重发两次，两个人都拿到了对方的东西；对方在锁定后被踢下线，物品卡在托管里，客服手动补发之后原来的托管又结算了一遍；跨服交易遇到老版本客户端，新物品显示成问号，点确认后物品消失；两笔交易同时引用同一堆可堆叠矿石，两边都成交，矿石总数凭空多出一倍；取消交易后托管箱没清空，维护重启又按旧记录发了一次货；还有玩家发现交易窗口关了再开，上次锁定的数量还留着，随手一点就成交了。trade_window_escrow.py 里的 TradeWindowEscrow 管挂单、锁定、确认、取消和掉线恢复。同一张交易单并发确认只能成一笔，后到的要返回 trade_already_settled 且两边资产一分不动；背包、托管箱和对方背包里的物品数量加起来必须守恒，任何时刻不能多也不能少，交易期间物品被强化、拆解或转移时整单失败，双方锁定状态一起清掉；金额超过上限要抛 CurrencyOverflowError，负数、零和超出背包容量的数量一律拒绝，不许截断成负数；进程被 kill 后重启，未完成的交易要么回到待确认，要么整单撤销，不能出现扣了钱没给货。交易行这摊子我盯了两周，先把托管、背包和对方资产三处对平，别再让客服手工补货。
