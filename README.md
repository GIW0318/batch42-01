# GSB Bugfix Task
## 题面
批处理平台跑一个抓取任务时把整机的文件句柄耗尽，sshd 和监控代理一起报错。fork 出来的子进程继承的是父进程的软限制，硬限制却被重置成无限；提升硬限制时跳过特权能力检查，普通用户也能改到很高；软限制被设置成大于硬限制，调用返回成功但后续全部失败；多线程进程里一个线程改了限制，其他线程读到的还是旧值；把文件句柄上限调低后已经打开的描述符不受影响，新建描述符失败时错误码又指向别处；systemd 单元里配的限制和进程内设置互相覆盖，后设置的赢了；CPU 时间软限制触发信号后没有宽限期，进程被直接杀掉；进程数限制按真实用户统计，容器里的映射用户全部算到了宿主用户头上；限制值用三十二位整数解析，超过上限回绕成负数；子进程 exec 之后限制被重置，本该保留的硬限制丢了；配额恢复后没有重新核对当前用量，下一次分配仍然失败。rlimit_inheritor.py 的 RlimitInheritor 要把软硬限制作为一组来校验，提升硬限制必须有对应特权，父子进程和线程之间的可见性按内核语义处理，限制值用六十四位解析并检查范围，exec 前后保持应继承的项，配置落盘并在重启后恢复，同一进程内多线程修改限制必须串行。test_rlimit_inheritor.py 那十五条检查从上线那天红到今天。

## 运行方式
```bash
python -m pytest tests -q
```
