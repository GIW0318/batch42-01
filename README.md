# GSB Bugfix Task
## 题面
电信信令侧换成 SCTP 承载以后，多流并发时延抖动得厉害，值班同事一直在查。多条流同时发消息时接收端按全局顺序重组，一条流上的大消息把其他流全堵住；SSN 到六万多回绕后，接收端把新消息当成重复丢掉；PR-SCTP 已经放弃的消息还占着发送队列，队列越积越满；主路径切到备用路径后，累积确认把两条路径的 TSN 混在一起算；心跳超时按整条关联判死，其实只有一条路径不可达；两个线程往同一条流发消息，SSN 分到同一个号；进程重启后关联没有恢复，对端一直重传最后 ABORT；流数量协商时对端只支持八条，本地按三十二条发，超出的直接被丢；接收窗口降到零后发送队列仍在出队，缓冲涨到几个 G；AUTH chunk 校验失败，关联没有关闭，后面的数据照收；分片消息重组超时后缓冲区没释放，长时间跑内存一直涨；多宿主场景源地址选错，出口策略路由不匹配，包被防火墙丢掉。sctp_multistream_guard.py 的 SctpStreamGuard 得按流和路径分别维护状态。四条必须达成的行为：同一条流并发发送 SSN 必须严格递增且不重复；AUTH 失败必须以 ABORT 结束并带上精确 cause code；接收窗口为零时必须停止发送；进程重启后要保留未确认 TSN 和流状态继续投递。test_sctp_multistream_guard.py 的十五条我是从后往前跑的，十五条全失败。
