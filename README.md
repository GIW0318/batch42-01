# GSB Bugfix Task
## 题面
组播源从旧机房切到新机房后，会议室大屏一直黑着，RP 上的加入表却显示正常。抓包发现 (*,G) 表项和 (S,G) 表项各记各的，源切换后上游接口没跟着改，旧表还挂在出接口列表里；Join/Prune 携带的保持时间到期后表项不删，僵尸条目把表撑到上限；Prune 里的源地址列表长度字段被改大时解析器继续往后读，解出了负的组地址；同一个接口重复发 Join，出接口被追加两次，一份流复制成两份；RP 选举只比优先级，哈希值完全没用上，几百个组全压到同一台；Register 封装不检查内层源是否直连，任意主机都能注册一组合法组地址；收到 Register-Stop 之后仍继续封装注册报文，RP 带宽被白吃；Assert 落败的接口没有从出接口列表裁剪，双向转发绕成环；SSM 的 (S,G) 加入被送进 ASM 流程，源过滤失效；表项数量触顶后新 Join 被静默丢掉，接收端毫不知情；设备重启后加入表清空，上游要等下一个查询周期才恢复。pim_join_registry.py 的 PimJoinRegistry 要把 (*,G) 与 (S,G) 的关联维护成一张表，表项更新和出接口列表要么一起生效要么都不动，保持时间到期必须回收，编码越界要抛出带字段位置的解析异常，重启后从持久记录恢复表项并主动重新加入。仓库里的 test_pim_join_registry.py 十五条断言目前没有一条站得住。

