# GSB Bugfix Task
## 题面
运维用脚本统一生成 sudo 策略，最近两次变更都放大了权限。别名循环引用，编译时递归到栈溢出；否定规则优先级反了，允许盖住了拒绝；主机别名和用户别名同名，解析到错误的表；命令通配符把带参数的调用也放行了，一个 sudo 后面跟任意命令都能跑，等于给了 shell；包含目录按文件名排序加载，后加载的覆盖先加载的；嵌套用户组只解析一层，二层组员没有权限；命令参数没做路径规范化，点斜杠和上级目录写法绕过限制；NOPASSWD 标签作用域泄漏到后面的规则；Defaults 按用户覆盖的顺序不对，安全项被业务项盖掉；并发 sudo 调用时编译缓存返回半成品；审计只记了命令名不记完整参数，出了事回放不出当时执行的内容；有语法错误的行被静默跳过，整段策略少了一条没人发现，查日志也看不出来。sudoers_alias_resolve.py 的 SudoersCompiler 要先完整解析再判权，不能边读边用。四条硬门禁：别名循环必须返回精确编译错误；否定规则必须优先于允许；通配命令不得匹配参数注入；缓存必须按内容哈希失效。test_sudoers_alias_resolve.py 的十五条检查现在全红，编译和匹配两条线都没过。

## 运行方式
```bash
python -m pytest tests -q
```
