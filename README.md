# GSB Bugfix Task
## 题面
运维把 SSH 和 sudo 的认证统一收口到 PAM 以后，线上出现了几起越权和登录串号。include 形成环，栈展开直接栈溢出；sufficient 排在 required 前面，前面的失败被后面的成功盖掉；并发登录时 pam 环境变量互相覆盖，A 用户的变量进了 B 用户会话；substack 失败后父栈还继续往下走；success=done 的跳转偏移算错，跳过了后面的账号检查；模块参数里带空格和引号，被解析成两个参数；账号过期检查放在密码验证之后，能枚举出账号是否存在；会话打开到一半失败，前面打开的模块没有关闭；配置热更新时读到写了一半的栈；同一服务有多个配置文件，按字典序加载，谁覆盖谁不确定；审计里记了用户密码；空栈或者解析失败时默认放行。pam_stack_eval.py 的 PamStackEvaluator 要按控制标志严格推演整条栈。硬门禁：空栈或解析失败必须拒绝并回 PAM_SYSTEM_ERR；控制流跳转必须严格边界，越界按解析错误处理；会话失败必须逆序关闭已打开模块；热更新必须原子切换。test_pam_stack_eval.py 的十五项检查眼下全部失败，栈展开和会话回收都没通过。

## 运行方式
```bash
python -m pytest tests -q
```
