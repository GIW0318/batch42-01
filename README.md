# GSB Bugfix Task
## 题面
容器平台批量下发内核参数之后，宿主机上的连接跟踪表被撑爆，几个业务同时超时。命名空间化的 net 参数被写到了宿主全局，所有容器一起受影响；本来就不可命名空间的参数从容器里写入也成功，越权改到了内核行为；两个租户并发写同一个参数，后写的直接覆盖，审计里查不到前一次；写入值带单位和空白没有归一，非法值被截断后当成合法；只读参数返回权限错误，代码却当成写入成功；批量写入到第五个参数失败，前四个已经生效，没有回滚；参数之间有依赖顺序，先调大表项再开转发，顺序反了直接把内存打满；取值范围用三十二位整数判断，超过上限回绕成负数；重启后参数恢复默认，落盘配置没有生效；读取时拿到的值来自另一个命名空间，判断依据是错的；已经废弃的参数写入被静默忽略，调用方以为成功。sysctl_scope_writer.py 的 SysctlScopeWriter 要按参数的作用域决定写入位置，容器内只允许命名空间化且非特权的参数，批量写入失败时整体回滚，值按参数类型做范围校验，重启后从持久配置恢复，跨命名空间读写在审计里带上命名空间标识，同一命名空间内的并发写入要串行。test_sysctl_scope_writer.py 十五条用例眼下全是失败状态。

## 运行方式
```bash
python -m pytest tests -q
```
