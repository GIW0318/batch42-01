# GSB Bugfix Task
## 题面
两个机房之间的 IPsec 隧道这周断了三次，每次监控都显示 up，实际业务已经不通。两条选择器重叠的策略优先级相同，匹配结果取决于哈希遍历顺序，每次重启选中的都不一样；策略更新后旧 SA 没失效，流量还在用弱加密算法；并发下发策略时查询线程读到写了一半的表，一半流量走旧隧道；重启后 SAD 没恢复，隧道实际断了但监控还是绿的；NAT-T 之后对端端口变了，SA 查找还按原端口找，回程包被丢；同一对端配了两个子网，10.1.0.0/16 的流量被送进 10.1.2.0/24 那条隧道；策略删除后关联 SA 泄漏，SA 计数一直涨；双向策略有一侧没配，去程加密回程明文，被上游 IDS 告警；多核下重放窗口共享一个计数器，序号错乱，合法包被当重放丢掉；对端提议 group1 的 DH，本地接受了，协商出七百多位密钥；查询每包遍历整张策略表，十 G 口一压就丢包；SA 生命周期到期和重协商撞在一起，出现几秒没有可用 SA 的空窗。ipsec_policy_lookup.py 的 IpsecPolicyTable 要保证策略、SA 和选择器三者同步。四个硬门禁：同时下发两条冲突策略，第二条必须被拒绝并返回 EEXIST；删除策略必须原子撤销关联 SA，计数归零；重启后 SA 与策略必须一一对应；弱 DH 组必须拒绝并回 NO_PROPOSAL_CHOSEN。test_ipsec_policy_lookup.py 的十五条用例现在全挂，策略查找和 SA 同步两边都没过。

## 运行方式

```bash
python -m pytest tests -q
```
