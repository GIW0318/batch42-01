# GSB Bugfix Task
## 题面
卡牌新赛季更新后，天梯上出现了一堆明显违规的卡组。禁卡表已经生效，老卡组还能直接进匹配，对手在开局看到被禁的卡；卡组里塞了三张同名卡，界面只标红不阻止开赛，匹配队列照常放行；导入别人分享的卡组，卡牌ID对不上，系统静默替换成基础卡；两个人同时编辑同一个卡组，后保存的把前一份整个覆盖，连提示都没有；英雄专属卡混进通用卡组，客户端能存，进对局才报错；卡牌被削弱后费用变了，卡组合法性还按旧数值算；备牌上限十五张，复制粘贴能塞进二十张；匹配成功那一瞬间改卡组，开局用的是旧卡组，对手看到的却是新卡组；赛季重置后卡组引用已下架卡，一打开就崩溃；导出文件没写版本号，老客户端导入新格式直接一片空白，连错误提示都没有；同名卡一张闪卡一张普通卡，复制上限被当成两种卡各算三张；有张卡被移出标准模式，客户端还能保存，进对局才提示未知卡。deck_builder_legality.py 的 DeckBuilderLegality 管校验、保存、导入、导出和开赛快照。保存时必须按当前 ban_list_version 校验，非法卡组抛 DeckIllegalError 并列出具体违规项，同一份卡组两次校验结果要一致；同一个卡组并发保存用版本号做乐观锁，旧版本写入返回 stale_deck；匹配开始时冻结卡组快照，之后怎么改都不影响这一局；导入遇到未知卡牌ID必须整包拒绝，不能静默替换成别的卡，也不能只导入一半。校验结果要能区分禁卡、超限和英雄归属，每种违规要带卡牌ID和规则版本，客服解释时不能只给一句不合法。天梯上违规卡组越来越多，先把校验和开赛快照扣在一起。

## 运行方式
```bash
python -m pytest tests -q
```
