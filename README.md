# GSB Bugfix Task
## 题面
公司强制全员开 MFA 之后，IT 服务台被绑定问题淹没，安全那边还发现了几处绕过。同一用户并发绑两个认证器，后写的把先写的覆盖，旧的还能用；绑定确认码可以无限试，没有锁定；备份码生成后明文存库；绑定页面刷新一下，产生半绑定状态，既不能登录也不能重绑；客服恢复流程绕过 MFA，只凭身份证号就能解绑；设备删除后旧 secret 还能生成有效验证码；TOTP 窗口给了正负十步，同一个码能用好几次；策略要求全员 MFA，但新用户有七天宽限，宽限还能被重置；服务器时钟漂移后合法用户全被拒；绑定审计没记操作者；同一个 TOTP 码并发验证两次，两次都通过；手机号换了以后旧号码还能收备用码；换手机后旧设备上的绑定没有解绑，验证码还能收到；服务重启后未完成的绑定没有恢复，用户只能重新扫码。mfa_enrollment_ledger.py 的 MfaEnrollmentLedger 要按用户、设备和验证码三层记账。门禁四条：同一 TOTP 码只能成功一次，重放必须拒绝；并发绑定只保留一个 active 认证器；删除设备必须立即失效 secret；强制策略下宽限不得重置。test_mfa_enrollment_ledger.py 的十五条用例刚从 CI 上拉下来，一条都没过。

## 运行方式
```bash
python -m pytest tests -q
```
