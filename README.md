# GSB Bugfix Task
## 题面
公司邮件网关最近被外部审计指出会把内部信件明文发出去，运维查了几天也没找到规律。对端不支持加密时网关直接降级继续投递，没有按域策略拒投；域策略缓存过期以后仍按旧策略放行，新配置要等半天才生效；TLSA 记录查询超时被当成校验通过，等于没做证书绑定；证书链验过了但主机名没比对，MX 指向别处也照样通过；同一域名并发投递时每个连接各查一次策略，缓存击穿把上游 DNS 打限流；策略热更新后老连接还在用旧版本，新连接和老连接行为不一致；一个域有多个 MX，只要有一台不支持加密，整批邮件都降级；加密失败进入重试队列后无限重试，队列堆到几十万封；对端返回临时错误时被当成永久失败，邮件直接退信；内容协商降级后 8 位字符被截断，附件损坏；审计只记了队列编号，没有记录策略判定结果；网关重启后队列里的邮件丢了策略上下文，恢复后按默认明文发出去。smtp_starttls_policy.py 的 StartTlsPolicy 要按收件域维护策略版本，并在投递前完成一次判定。硬门禁：策略要求加密而对方不支持时必须拒投并回 deferred 加上具体策略原因，不能明文；TLSA 查询失败必须按失败关闭处理；策略热更新后新连接立即用新版本，老连接在下一封信前关闭；重启后队列恢复必须带回原策略上下文。test_smtp_starttls_policy.py 的十五项检查眼下没有一条能过，投递和策略两块一起红。

## 运行方式
```bash
python -m pytest tests -q
```
