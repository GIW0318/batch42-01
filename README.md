# GSB Bugfix Task
## 题面
构建集群的磁盘又一次被写满，告警显示几个项目的用量早就超过了配额。配额按用户统计而不是按项目编号，跨项目互相占用额度；硬限制只查数据块数量，不查 inode，小文件把索引节点耗尽；宽限期从项目创建时间算起，而不是从第一次超限的时刻算；多个进程同时写文件，各自看到的剩余额度都够，合计超卖了几十吉；删除文件后配额延迟回收，用户短时间内无法再写；父项目的限制没有向下取最小值，子项目能超过父项目；硬链接和符号链接被重复计数；rename 和 truncate 这类元数据操作绕过了配额检查；超限时返回空间不足，但一部分数据已经落盘；快照和备份目录没有计入配额，可以无限增长；修改配额对已经打开的文件句柄不生效；配额统计把稀疏文件按表观大小计算，实际占用被放大十几倍。project_quota_enforcer.py 的 ProjectQuotaEnforcer 要在写入前原子预留额度，块和 inode 两本账同时校验，宽限期从首次超限起算，项目树按父链取最小限制，超限返回明确的配额错误而不是笼统的空间不足，重启后从磁盘重建用量并核对。test_project_quota_enforcer.py 的十五条检查在构建集群复现，整组报错。

## 运行方式
```bash
python -m pytest tests -q
```
