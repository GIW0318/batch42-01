# GSB Bugfix Task
## 题面
录屏工具更新后，主播那边的投诉没停过。录出来前三十秒音画同步，后面声音越来越早；高刷屏录游戏，一百二十帧输出成六十帧文件，运动镜头一卡一卡，慢放能数出重复帧；HDR游戏录成SDR，天空过曝，UI颜色发灰，调色也救不回来；竖屏游戏录出来是横的，旋转元数据没写进去；双显示器录制，鼠标移到副屏后录像里光标消失，客户以为鼠标坏了；暂停再继续，时间轴少一段，音频却还是连续的；编码器突然掉线，录制没停，文件最后损坏打不开，日志里只有一行失败；游戏切全屏，捕获源失效，后面全是黑屏，要重新选源才恢复；录制中改分辨率，文件后半段花屏，后面的音频也跟着断；一小时的文件没有关键帧，拖进度条要等很久，剪辑软件导入也找不到画面；录制时切窗口，捕获区域跟着窗口跑，画面一半是桌面；麦克风和系统声分别编码，时间基不同，解说总比画面慢半拍。screen_capture_pipeline.py 的 ScreenCapturePipeline 管帧采集、时间戳、音频对齐和文件封装。整段录制音画偏差要控制在固定阈值内，以第一个音视频包的时间戳为基准按单调时钟校正，长录制不能累积漂移；崩溃或断电后必须能从临时分片恢复出可播放文件，分片要能被播放器直接识别，不能整段丢；旋转和分辨率变化要写入新的轨道参数，不能沿用旧参数，旧轨道要正常收尾；丢帧要记录并在元数据里如实标注，不能假装满帧。暂停恢复的时间轴要连续，暂停期间的系统声音也不能混进来，恢复后的第一帧不能吞掉。主播那边的录屏样本我收了一堆，先保证音画和封装别再互相拖累。
