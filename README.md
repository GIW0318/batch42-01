# GSB Bugfix Task
## 题面
音乐组的工程导出最近频繁翻车。导出分轨再导回来，鼓组整体晚了七毫秒；总线挂了限制器，导出比不挂时短一截，尾巴被切掉；独奏某轨导出，其他轨的自动化还在跑，结果音量不对；四十八k工程导出四十四点一k，镲片出现金属味，时长也差几毫秒；导出时改了个插件参数，前半段和后半段音色不一样；导出到一半磁盘满，留下半个文件，工程却标记为已导出；静音轨道仍被渲染进分轨，只是音量为零，文件体积没变，后期还得再删一遍；多个片段首尾相接处有爆音，导出前监听却听不出来，交叉淡化没生效；崩溃后重开工程，导出队列清空，已渲染的分轨找不到；总线峰值超过零dBFS，导出削波但界面没有报警，回放时才发现已经削平；导出时改了采样率，自动化曲线的时间没跟着换算，淡出位置整体偏移，重新导出也复现不了；分轨文件名按轨道名生成，两条同名轨道互相覆盖，少导一轨，只能按文件名手工找。multitrack_render_mixdown.py 的 MultitrackRenderMixdown 管分轨渲染、延迟补偿、导出事务和恢复。分轨总和要和总线导出在容差内逐采样一致，静音和独奏状态按导出时的快照算，不能少轨或多轨；插件延迟补偿要按采样精确对齐，导出和实时播放的偏移一致；导出必须原子，要么生成完整文件并更新工程状态，要么全部回滚，失败时临时文件要清理；崩溃恢复要从已完成分轨继续，不能重复渲染也不能漏轨。片段交叉淡化要按采样算，淡入淡出曲线也要按采样点写进文件，别用毫秒取整。音乐组每次导出都要人肉对轨，先把延迟补偿和导出事务做扎实。

## 运行方式
```bash
python -m pytest tests -q
```
