# GSB Bugfix Task
## 题面
固件元数据服务用 CoAP 给设备传升级包，最近大包上传十次有八次坏。Block1 的块大小传到一半从 1024 变成 512，接收端还按第一块的尺寸拼，后面全部错位；资源 ETag 变了以后还在拼接旧块，最终文件是新旧混合；块乱序到达时直接按到达顺序写缓冲，中间缺的那块被后面的块覆盖；重复块被重复追加，最后算出来的摘要对不上；服务端回了 4.13 Request Entity Too Large 和 Size2，客户端没按新尺寸重发，一直卡在同一个块；两个客户端用同一个 token 往同一个资源上传，块缓冲互相污染；块号是 16 位，超过六万多块之后回绕，组装循环停不下来；最后一块 M 位为 0 之后，服务端还在等后续块，直到超时才回错误；上传超时后临时文件没有清理，一天下来磁盘被占满；不支持 blockwise 的老客户端收到 2.31 Continue 不知道怎么办，连接挂住；代理转发时把 Block1 选项丢了，源站收到的是不完整实体；单次上传没有总大小上限，一个两 G 的 body 直接把进程打崩。coap_blockwise_assembler.py 的 CoapBlockAssembler 得把重组窗口、ETag 和总大小一起管住。门禁四条：缺块必须回 4.08 Request Entity Incomplete，不能回 2.31；同一个 token 的并发上传只允许一个成功，另一个回 4.09 Conflict；ETag 不符时整个重组丢弃，不能拼接；重启后未完成的上传要么续传要么明确失败。test_coap_blockwise_assembler.py 的十五条现在一条也跑不通，全卡在组装那一步。
