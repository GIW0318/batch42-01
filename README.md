# GSB Bugfix Task
## 题面
团本换了新首领以后，仇恨表每天都得手动擦屁股。坦克开场嘲讽，首领转头打了三秒治疗，嘲讽像没生效；治疗职业的实际仇恨按治疗量的一点五倍涨，配置写的是零点五，改配置文件重启也不生效，治疗一直被秒；主坦倒下后副坦接不住，仇恨表里还留着死人的记录，首领对着尸体冲锋；灭团重置只清当前目标那一行，其他人的仇恨还在，下一把开场就乱；猎人宠物的伤害记在宠物名下，主人被 OT 时宠物也跟着挨打；首领读条期间处于无敌，治疗还在偷偷刷仇恨，这段时间的伤害照样加账；战斗暂停时仇恨衰减还在跑，恢复后坦克的领先优势没了；分裂出来的小怪继承本体全部仇恨，一出生就冲治疗；盗贼隐身降低仇恨的被动没算进去，消失之后首领还锁着他；跨场景传送后旧仇恨表没清，新地图的第一只怪直接冲后排；仇恨更新走两个线程，同一帧的两次加仇只落了一次；同分时按数组下标取目标，每次都打到不同的人。threat_table_registry.py 的 ThreatRegistry 要把伤害、治疗、嘲讽、隐身和死亡事件统一成带序号的事件流，同一事件编号重复提交只加一次，乱序到达按序号补账；仇恨快照要能持久化，服务重启后原样恢复，已经结算的事件不能重放；目标选择按仇恨降序、同分按加入时间升序，顺序必须稳定；嘲讽是带截止时间的强制状态，到期自动回到正常排序，事件里的角色编号不存在时抛 UnknownCombatantError。团里的坦克已经不敢开怪，治疗进本先问仇恨表修没修，先把仇恨和死亡清理做成一条事件流。

## 运行方式
```bash
python -m pytest tests -q
```
