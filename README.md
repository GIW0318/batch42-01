# GSB Bugfix Task
## 题面
跨服聊天合并以后，频道里的消息开始乱序。世界频道发一句话，隔壁服的人三秒后才看到，后面的消息先到，前面的消息补不上；同一个账号在两个服同时发言，两边各显示一条，屏蔽列表只在一服生效；频道人数上千时，一条消息被拆成多个包，接收端按到达顺序拼，句子中间串行；玩家改名后历史消息还挂在旧名字下，举报时找不到人；禁言只禁了当前服，切到另一个服照样能发；聊天服务器重启后，最近一小时的公共频道记录全没了；敏感词过滤在分片之后做，跨包的词拼起来就漏过去；私聊和队伍频道共用一条连接，私聊发太快把队伍消息挤掉；频道权限按角色等级判断，管理员小号进不去管理频道；同一条消息被两个网关各转发一次，接收端看到重复；客户端断线重连后补拉历史，补拉的和实时推送交错，时间轴倒着走；频道切换时旧频道的订阅没有取消，消息继续往新窗口里灌。chat_channel_fanout.py 的 ChannelFanout 要把频道订阅、消息序号和权限检查分开，每个频道一条单调递增的序号，消息按序号排序后再投递，跨服转发保留原序号，客户端按序号去重和补洞；同一发送请求带请求编号，网关重复转发只落一条；禁言、屏蔽和频道权限在服务端统一判定，客户端只做展示；服务重启后从持久化的最近消息恢复，订阅关系按连接重建，频道编号不存在、无权发言和消息超长分别抛 ChatError 的不同错误码。运维那边导了两天的频道日志。压测脚本跑了两轮，第二轮比第一轮还多出两种。

## 运行方式
```bash
python -m pytest tests -q
```
