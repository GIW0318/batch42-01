# GSB Bugfix Task
## 题面
骨干网做 TE 隧道重优化，两条 LSP 在切换时同时断了十几秒。Path 消息和 Resv 消息里的跳列表对不上也被接受，资源被预留到了错误节点；刷新定时器按本地墙上时钟算，进程重启后所有 LSP 在同一秒超时；ERO 里的 loose 跳按 strict 处理，路径算出来绕了一大圈；抢占优先级比较方向反了，高优先级隧道被低优先级踢掉；入标签分配重复，两条 LSP 抢同一个标签；PathTear 只清了本地状态，下游没收到，标签一直占着；管理组位图匹配用了按位或，隧道走上了没有对应亲和性的链路；带宽预留没有扣减共享链路，账面上超卖了百分之四十；优雅重启恢复的 LSP 没有和 ERO 逐跳核对；PathErr 返回后没有删除半成品状态，下一次建立直接冲突；同一隧道并发发起两次建立，产生了主备两条 LSP。rsvp_lsp_planner.py 的 RsvpLspPlanner 要让 LSP 状态和标签、带宽预留三者一起提交，抢占按数值优先级比较，ERO 的 loose 和 strict 分开处理，重启后从持久状态恢复并重新核对路径，标签重复和带宽不足时抛出明确原因，同一条 LSP 的并发建立必须串行。test_rsvp_lsp_planner.py 那十五个用例今天在实验网跑了一轮，全都没通过。

## 运行方式
```bash
python -m pytest tests -q
```
