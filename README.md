# GSB Bugfix Task
## 题面
城域环割接后，两台 PE 之间的 LDP 会话抖了三次，恢复后部分 VPN 流量被送到错误邻居。Label Withdraw 到了以后只删了本地入标签，FEC 到下一跳的映射还留着，转发面继续用旧标签压包；同一个 FEC 被邻居重复宣告，新映射直接盖旧映射，没有序号或版本可比较；会话 down 时标签池没回收，进程重启后可用标签少了一大截；两条路径宣告同一前缀，选路只看谁先到，不看本地优先级和度量；Label Request 与 Label Release 乱序到达，刚释放的标签立刻又被分配出去；MD5 认证只在建立会话时校验第一个包，后续消息不再验摘要；传输地址变化后仍复用旧 TCP 偶联，会话表和标签表指向不同邻居；标签空间耗尽时返回标签零，而不是明确的资源耗尽错误；环路检测的 TTL 减到零以后报文还是被转发；Notification 里的状态码不分类，致命错误按警告处理继续跑；优雅重启保留的标签在邻居重连后没有逐条核对。ldp_label_ledger.py 的 LdpLabelLedger 要求 FEC 与标签的绑定在一次操作里完成，重复宣告和撤销按消息序号幂等，标签池在会话断开和进程重启后都能回到一致状态，非法标签和越界 TTL 要抛出明确异常，重启后先对账再恢复转发。test_ldp_label_ledger.py 的十五项检查昨晚连跑三遍，三遍全红。

## 运行方式
```bash
python -m pytest tests -q
```
