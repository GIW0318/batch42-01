# GSB Bugfix Task
## 题面
RTS 新操作方案上线后，高分段玩家先炸了。框选一队兵按 Shift 排队，最后一个命令总是丢，界面还显示已排队，走到半路就停；攻击移动途中点停止，队列没有清空，单位又自己回去打；编队里死了一个单位，空出来的编号没有补位，后面的编号整体前移，按 3 号出来的是另一个兵种；框选会把战争迷雾里的敌人也选进来，点攻击直接冲进埋伏；阵型移动时单位互相挤开，坦克被挤到后排；路径被新盖的兵营堵住，整队围着建筑转圈，不会重新寻路；队列里的建造命令在资源不够时被跳过，但界面还显示排队中；网络延迟高的时候点地面，单位走到点击时的旧位置，不是服务器当前位置；回放里的命令顺序和玩家实际操作顺序不一致，复盘看不出问题；一次给两百个单位下发命令，服务器在同一帧处理完，卡了三百毫秒；设置集结点以后，新生产的单位还是从兵营门口发呆；取消队列里的最后一项，前面几项也被一起清掉。command_queue_dispatch.py 的 CommandDispatch 要把命令按玩家、单位和逻辑帧排序，同一帧内的命令保持提交顺序；每条命令带客户端序号，服务端按序号去重，重复下发只执行一次；队列操作是原子的，插入失败要恢复原队列，替换和清空不能留下半个队列；服务器重启后从快照恢复每个单位的队列和当前执行项，非法目标、已死亡单位和超出队列长度的命令分别返回错误码。我们拿二十局录像逐帧对过。复盘的时候我们把选手操作和服务器命令并排放，队列顺序根本对不上。

## 运行方式
```bash
python -m pytest tests -q
```
