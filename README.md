# GSB Bugfix Task
## 题面
流量分析平台重启采集器之后，同一批导出器的字段全部错位，端口被解成协议号。模板编号只在进程内全局唯一，没有按 observationDomainId 分域，两个域用了同一个编号时后到的模板把前一个顶掉；模板撤销消息到达后缓存仍然命中，数据记录按已撤销的模板解码；数据记录比模板先到，采集器直接丢弃而没有暂存等待；模板重复定义时没有版本概念，旧定义覆盖新定义；Options Template 的作用域字段没有解析，采样率被算成总包数；导出序列号跳变和回绕没有检测，丢包被当作正常波动；变长字段的长度前缀为二百五十五时继续读扩展长度，读到了下一条记录的头部；单个模板的字段数超过上限被截断，最后几个字段永远注册不上；采集器重启后模板表清空，收到数据记录也不向导出器请求重发；同一模板两次定义字段顺序不同，按第一次的顺序解码导致整体偏移；UDP 截断的模板报文按完整报文送去解析。ipfix_template_index.py 的 IpfixTemplateIndex 要按域隔离模板编号，模板带版本并拒绝旧版覆盖，数据早于模板时先入暂存区，撤销后立即失效，重启后从磁盘恢复模板并主动重同步，长度和字段数越界时抛出指明模板编号的异常。这套 IPFIX 用例挂在 test_ipfix_template_index.py 下，十五条至今没绿过。

## 运行方式
```bash
python -m pytest tests -q
```
