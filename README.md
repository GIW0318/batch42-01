# GSB Bugfix Task
## 题面
直播主备切换上线后，观众反馈卡顿反而更多了。主源断流以后过了八秒才切到备源，健康检查还在等三次超时，观众那边早就黑屏；切过去时间戳往回跳，播放器卡在最后一帧，拖进度条也回不来；备源的音频和视频不同步，口型差半秒；备源分辨率比主源低，码率却更高，切完又卡又糊，画面没有重建；主源恢复以后又切回去，两个源来回跳，一分钟切了六次；录制文件在切换点断成两个，后一个没有文件头；备源的鉴权令牌过期，切过去连不上，回切也失败；切片序号在切换时重复，播放器一直重试同一个分片；切换时正好丢了一个关键帧，后面几十秒全是花屏；多路备源按配置顺序选，第一路挂了不会试第二路；切换后码率没有重新协商，带宽不够一直缓冲；主源只是抖动了一下，健康检查就判死，触发不必要的切换。stream_failover_switch.py 的 FailoverSwitch 要把源健康、切片序号和输出会话分开，每个切片带全局递增序号和源编号；切换只在切片边界发生，切片内不换源，新源从关键帧开始，时间戳连续；同一路源重复切换请求按请求编号幂等，不能反复重建输出，主源恢复后要连续健康一段时间，回切也要走同一套确认，避免切换风暴；音视频时间戳来自同一时钟，切换后保持同步，切片序号重复、源地址为空或鉴权失败抛 StreamSourceError，进程重启后从最后成功切片继续，已输出的切片不能重发。运维把一周的切换日志按时间排开。两路测试流我断断续续跑了一周，问题基本都踩过。
