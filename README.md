# GSB Bugfix Task
## 题面
长视频平台换了密钥轮换方案，播放端问题集中爆发。密钥一换，播放器在切换点卡住，要手动重试才继续；离线下载的剧集过期后，删掉再下载提示已拥有却不能播；两个孩子账号共用家庭组，家长的观看权限被孩子设备继承；许可证服务器比CDN快两分钟，密钥提前失效；同一账号五台设备同时播放，第六台把第一台踢下线却没有提示，被踢的设备还能靠缓存继续播；切集时旧密钥缓存没清，新集用旧key解密失败；低版本播放器不识别新密钥格式，直接黑屏也没有错误码，客服只能让用户升级；断网重连后从错误分片续播，进度条也跟着倒退，画面跳回上一集；密钥请求并发太多被限流，播放器把限流当永久失败，重试间隔还越来越长；下载任务后台被杀，残留分片占满存储又无法续传，重新下载又从头开始；同一账号在手机和电视上同时播放，电视提示登录失效，手机还能继续；密钥轮换和广告插入撞在一起，广告段用错密钥，画面花屏。hls_drm_key_rotation.py 的 HlsDrmKeyRotation 管密钥分发、许可证、设备绑定和续传。同一license只能绑允许的设备数，超限返回 DeviceLimitExceeded，解绑后要立即释放名额，不能静默踢人；密钥轮换点要无缝续播，轮换前后的分片各用各的密钥校验，不能混用，音视频不断也不重复分片；离线许可证过期精确到服务端时间，客户端改时间无效；并发续传同一任务只能有一个写入者，第二个返回 download_in_progress。密钥和分片要能按节目单回查，轮换前后的密钥版本也要能对上，客服定位失败时能看出是哪一段。播放端的密钥问题跨了好几个版本，先把轮换、设备和续传三处对齐。
