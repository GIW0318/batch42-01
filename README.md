# GSB Bugfix Task
## 题面
高校联赛的淘汰赛对阵表出来后，裁判组一晚上没睡。六十四强有轮空，第二轮对阵表把轮空选手排进了两个位置；两场比赛同时结束，两个胜者被写进同一个八强槽位，另一个人无处可去；选手迟到被判负，判负结果重复提交，下一轮直接多打一场；改期之后旧比赛还能提交结果，胜者被推进了两次；三四名决赛和决赛排在同一时段，同一支队伍被拉进两个房间；服务器重启后对阵表回到开赛前，已经打完的比赛要求重打；种子分相同按报名时间排，跨时区报名显示的顺序和实际相反；弃权后对手自动晋级，弃权者的奖励邮件照发；裁判手动改比分把历史记录覆盖了，申诉时查不到原结果，也看不到是谁改的；客户端缓存的对阵表跟服务器不一致，选手点了开始却进不去；轮空选手在第二轮被系统当成弃权直接淘汰，申诉时找不到轮空标记；同一场比赛两个裁判同时提交比分，系统把两套比分都存了下来。tournament_bracket_seeding.py 的 TournamentBracketSeeding 负责抽签、轮空、晋级、改期和修复。每场比赛结果只能推进一次，重复提交返回 bracket_advanced；同一个槽位并发写入只认一个胜者，另一个进冲突待裁，不能两个都写；重启后对阵表、比分和晋级关系从快照恢复，不能回到开赛前，也不能把已结束的场次复活；弃权要同时结束比赛并取消奖励，两件事在同一个事务里。重赛要生成新的场次ID，旧场次的结果留档备查，改期只改时间，不能把已经打过的场次变回未打，改期记录要留操作人和原时间。裁判组那边还在等赛程，先把晋级和改期的顺序固定下来。

## 运行方式
```bash
python -m pytest tests -q
```
