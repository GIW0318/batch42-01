# GSB Bugfix Task
## 题面
电视端和命令行工具接开放平台，走的是设备码授权，最近被发现能拿到别人的账号。用户码只有四位而且按顺序生成，能猜到别人的；客户端不按约定间隔轮询，服务端也不回 slow_down；设备码过期后还能兑换令牌；同一个用户码并发批准，绑到两个不同用户；用户没登录就点了批准，授权落到了匿名会话；兑换时没校验应用编号，任意应用都能拿；用户拒绝之后设备码还有效；轮询限流按 IP 做，换 IP 就能绕过；授权服务重启后待处理记录全丢；批准页展示的授权范围和实际签发的不一致；长轮询把线程池占满，正常请求排队；审计里没有用户码和应用编号的关联；设备码按用户码排序存储，扫描器能顺序枚举；轮询间隔只存在客户端，服务端没有按 device_code 记 last_poll；同一设备码被两个应用同时兑换，令牌发给先到的一方；批准页没有展示应用图标和申请范围，钓鱼应用能混进来；兑换成功后旧记录没有删除，重放还能再换一次；授权服务多实例部署，待处理表各存一份，轮询落到别的实例就查不到。device_code_flow_guard.py 的 DeviceCodeGate 要把用户码、设备码和应用编号三者绑定。硬性要求：同一用户码并发批准只成功一次；过期设备码兑换返回 expired；用户拒绝后立即失效；轮询过快返回 slow_down 且间隔递增。test_device_code_flow_guard.py 的十五条断言现在满屏红，授权和轮询都没过。

## 运行方式
```bash
python -m pytest tests -q
```
