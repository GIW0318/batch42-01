# GSB Bugfix Task
## 题面
一批新装的加密网关在机房反复出现启动卡死和密钥重复，厂商来了一趟也没定位。启动早期读 /dev/random 阻塞，服务等到超时；getrandom 带非阻塞标志返回了没初始化的数据，密钥强度不够；熵估计虚高，池子没满就标记 ready；虚拟机从快照恢复后熵状态重复，两个实例生成了一样的随机数；并发读取时锁竞争，吞吐掉到预算的三分之一；硬件 RNG 故障后没有回退到软件源；重启后种子没持久化，每次启动熵都是零，头几分钟的密钥全靠运气；用户命名空间里的普通进程能读到宿主的熵状态和种子文件；大量请求把池子抽干，系统卡住几分钟；熵源健康变化没有审计记录，硬件源坏了几个月都没人知道；混合多个熵源时权重算错，慢源拖累整体；服务退出时缓冲区没清零。entropy_pool_health.py 的 EntropyHealthMonitor 要把熵源、种子和消费者隔离开。硬性要求：快照恢复必须重新注入熵，产出不得重复；未初始化时不得返回密钥材料，必须回 EAGAIN；硬件源故障必须回退且状态可见；并发吞吐不得低于预算。test_entropy_pool_health.py 的十五条用例今天在虚机上复现，全部失败。

## 运行方式
```bash
python -m pytest tests -q
```
