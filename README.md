# GSB Bugfix Task
## 题面
大战场改成动态视野后，小地图上的红点开始骗人。单位走出视野半分钟了，迷雾还不恢复，那一块一直亮着；两队视野叠加时，敌人明明只被一队看到，另一队的客户端也能看见；高地遮挡没有算，隔着一整座山也能看到山顶的狙击手；隐身单位不显示模型，但小地图上一直有标记；侦察建筑被拆掉以后，它提供的视野还留半小时；客户端自己算视野，改一下内存就能全图可见；回放按当前版本的视野重新计算，和当时的实际视野对不上；每帧全图重算可见性，十万人战场 CPU 直接打满；队友掉线后他的视野残影还在，持续给情报；跨服观战能同时看到双方视野，还能看到隐身的单位，等于开了上帝模式；视野边界没有和地形网格对齐，一格一格闪，单位的可见状态在边缘来回跳；同一帧内两个队伍争夺同一个格子，结果取决于处理顺序。fog_of_war_reveal.py 的 FogReveal 要把视野计算放在服务端，客户端只收可见性快照；每个队伍维护独立的已探索位图和当前可见集合，两者分开存，可见性按格子版本号和队伍编号更新，旧版本的查询直接丢弃；同一单位在同一帧的多次视野提交按单位编号合并，不能重复扩张；服务重启后从已探索位图恢复，当前可见集合按存活单位和建筑重建，越权查询其他队伍视野抛 VisionDeniedError，大战场单帧计算超出预算时降低更新频率但保持结果单调。裁判组把两边的观战录像逐帧比过。裁判拿小地图截图和实际战斗画面对，红点位置每次都能差出半屏。

## 运行方式
```bash
python -m pytest tests -q
```
