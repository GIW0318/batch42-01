# GSB Bugfix Task
## 题面
邮件系统和目录服务共用 SASL 层以后，认证开始被降级，几个只允许强认证的账号被 PLAIN 登了进去。客户端列出的机制顺序被服务端重新排序，排在前面的强机制被挤掉；EXTERNAL 在没有客户端证书时也进入流程，空的授权身份落入匿名成功分支；initial response 的长度超过上限仍然继续读，内存被一条消息打穿；多轮 challenge 的状态挂在连接对象上，并发 bind 互相覆盖；授权身份和认证身份没有区分，可以替别人完成认证；机制名按大小写敏感比较，合法客户端被拒；GSSAPI 协商出的安全层是 none，服务端却仍然宣称链路已加密；认证中途 abort 之后套接字仍然可写，半认证状态留在会话里；失败次数按连接统计，换一条连接就能继续爆破；对端缺少信道绑定支持时静默降级，没有任何记录；机制列表里混入未知项时解析器越界。sasl_mechanism_negotiator.py 的 SaslMechanismNegotiator 要按双方共同支持的最强机制协商，EXTERNAL 必须有可验证的客户端证书，多轮状态按连接加锁并随 abort 清理，授权身份只能在认证身份允许的范围内，降级必须被拒绝并记录，未知机制抛出明确异常，重复 bind 按会话幂等。test_sasl_mechanism_negotiator.py 的十五项检查今天全红，协商和绑定两条线都没通。

## 运行方式
```bash
python -m pytest tests -q
```
