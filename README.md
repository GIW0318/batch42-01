# GSB Bugfix Task
## 题面
背包改成分页仓库以后，物品数量对不上成了日常。玩家把一组药水拆成两份，原格数量没减，凭空多出一组；两组九十九个的箭头合并，第二组直接清零，超出的部分直接消失，日志里只写合并成功；点整理以后，绑定的装备变成可交易，拍卖行那边立刻能上架；两个客户端同时拖同一格，服务端两个请求都成功，物品复制了一份；邮件附件取出来时背包满了，附件消失但背包里也没有；仓库翻页时同一种材料跨页合并，第二页的数量被清零；排序把同名但耐久不同的装备叠在一起，耐久取了两件里较高的那件；使用堆叠物品只扣了客户端，重连后数量又涨回来；服务器崩溃后临时拖拽格里的物品全部丢失，重连只恢复一半，没有任何补偿记录；背包扩容到两百格后，旧的一百格索引越界，打开就报错；出售时输入部分数量，结算却按整堆计价；把绑定物品放进公会仓库，取出后绑定状态丢了。inventory_stack_reconciler.py 的 StackReconciler 要把每次移动、拆分、合并和销毁记成带操作编号的日志，同一编号重放只落一次；背包、仓库、邮件附件和临时格的总数必须守恒，所有数量变更走同一本账；合并前先校验堆叠上限、绑定属性和耐久，超限拆成多格而不是丢弃；服务重启后从日志重放未完成的操作，已经提交的不能重复扣减，同格子并发写入用版本号比较，旧版本直接拒绝并抛 StackConflictError。运营把四个位置的计数截图发过来。我把背包、仓库、邮箱和临时格的数量打在同一个面板上，越看越对不上。
