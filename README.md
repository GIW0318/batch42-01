# GSB Bugfix Task
## 题面
只读镜像启用 fs-verity 之后，安全扫描发现被替换过的二进制仍然能正常执行。Merkle 树根没有和签名绑定，换一棵树再签一次也能过；块大小和哈希算法从文件头里读，攻击者改成弱算法后校验照样通过；文件末尾不足一块的填充没有参与哈希，尾部几个字节可以随意改；树层级计算差了一层，最底层的块校验被跳过；签名用的证书链没有验证，自签证书也能通过；启用 verity 之后仍然允许写入，描述符和文件内容对不上；并发读取时描述符被替换，校验用旧树去读新数据；大文件的树构建被超时中断，留下半棵树却标记为有效；同一 inode 在改名之后 verity 状态丢失；错误返回把 IO 错误和参数错误混在一起，调用方无法区分；摘要比较用了普通内存比较，虽然影响小但也不该这样写。fsverity_tree_checker.py 的 FsverityTreeChecker 要先把树根、签名和文件描述符绑定成一个整体，启用后写入必须失败，树构建、签名和标记要么全部完成要么全部撤销，并发读取用版本号校验描述符，证书链和算法白名单在验签前检查，重启后重新核对 inode 状态，并发读取时描述符与树版本保持一致。test_fsverity_tree_checker.py 的十五项断言跑了两遍，两遍都没通过。

## 运行方式

```bash
python -m pytest tests -q
```
