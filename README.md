# GSB Bugfix Task
## 题面
安全公司发来报告，说我们对外开放的 FTP 服务可以被人拿去做端口扫描跳板。PORT 命令里的地址跟控制连接对端不是同一个，服务端照单全收，攻击者能把数据连接指到内网任意主机；PASV 应答填的是内网网卡地址，经过 NAT 的客户端拿到的地址根本连不上；EPSV 和 PASV 混着用时，数据连接由谁发起判断反了；数据连接建立后不检查源地址，旁路主机可以往传输里塞内容；主动模式监听的端口从一个很大范围里随机挑，防火墙被迫整段放开；数据连接超时后不关闭，半开连接越积越多；REST 给的偏移超过文件长度仍然接受，接着 RETR 就读到缓冲区外；两个客户端同时对同一端口发 PASV，后到的把前一个的数据连接抢走；控制连接断开后数据连接还在传，传输永远不结束；匿名账号的可写目录和系统配置目录有重叠；STOR 的文件名里带上级路径，文件被写到用户根目录之外。ftp_bounce_arbiter.py 的 FtpBounceArbiter 要把控制连接与数据连接按五元组绑定，PORT 只允许指向控制连接的对端地址，被动端口在分配和释放时保持原子，数据连接必须核对源地址，越界偏移和路径穿越要报明确的错误码，端口分配在多线程下必须互斥。test_ftp_bounce_arbiter.py 的十五个用例现在整片报错，连正常路径都过不去。

## 运行方式
```bash
python -m pytest tests -q
```
