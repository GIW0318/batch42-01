# GSB Bugfix Task
## 题面
小区宽带换 BRAS 之后，装维师傅天天接到用户投诉，说账号被重复扣费、网时不时断。同一 MAC 并发拨号，BRAS 建了两条在线记录，计费出两份；会话编号回收后重用，旧会话的断开报文把新会话拆掉；BRAS 重启后在线表没落盘，用户还在线但计费从零开始；发现报文没有限速，一个小区广播风暴把 BRAS 打满；认证超时后迟到的响应仍然被接受，认证状态错乱；空闲超时和流量统计并发，正在下载的用户被误判空闲踢下线；同一账号多拨没有按策略限制，一个账号开了二十条在线；最大传输单元协商失败后回退到 1492 而不是拒绝，导致大包全丢；在线记录释放时队列参数没清理，跑一周后句柄耗尽；认证失败次数没有累计，暴力破解随便试；服务名大小写不同就匹配不上，用户被分到错误域；批量下线时停止计费报文发失败没有重试，账一直挂着。pppoe_access_registry.py 的 PppoeAccessRegistry 要按 MAC 和会话编号双键管在线状态。硬要求：同 MAC 并发拨号只允许一条在线记录成功，第二条收到明确拒绝；重启后在线记录从持久化恢复且不重复计费；断开报文必须同时校验会话编号和 MAC 才生效；认证失败超过阈值必须锁定账号。test_pppoe_access_registry.py 的十五项检查昨晚压测时全军覆没，一条都没立住。

## 运行方式
```bash
python -m pytest tests -q
```
