# GSB Bugfix Task
## 题面
学校 WiFi 漫游的计费代理这两个月账单对不上，财务隔三差五来问。NAS 重传的计费开始报文每次都新建会话，同一个会话编号在账本里能出现四五条；中间计费报文到达顺序颠倒，后到的旧流量值覆盖新值，用户已经用掉的流量在账单上倒退；停止报文比最后一条中间报文先到，会话关闭后又被迟到的中间报文重新打开，账一直挂着不结束；代理进程重启后内存里的会话表没了，后续停止报文找不到对应会话，回一个确认就丢掉；会话编号带前后空格或者大小写不同，被当成不同会话；关联键只用了用户名，同一账号手机和笔记本同时在线，两条会话的流量合并成一份；停止报文重传没有幂等，上游收到两次出账；请求鉴别器没有校验，或者拿隔壁 NAS 的共享密钥去验，伪造包能写进账本；NAS 重启后复用同一个会话编号，新会话被并进三个月前的旧账；中间报文间隔被配成五秒，一千台 NAS 同时上报，上游计费接口直接限流；计费响应要等上游回执，慢的时候整个认证线程阻塞十秒以上；未知的计费状态被当成开始处理。radius_acct_ledger.py 的 RadiusAcctLedger 要按会话标识做幂等账本。硬要求：同一会话编号的重复开始报文只落一条并回 duplicate；停止报文重复只允许出一次账；重启后未结束的会话必须从快照恢复；鉴别器不符的包必须丢弃且不写账。test_radius_acct_ledger.py 那十五个用例现在跑出来一片红，连第一条都没过去。

