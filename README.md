# GSB Bugfix Task
## 题面
文件服务器的 SMB 共享最近被安全扫描挑出一堆问题，客户端也经常报签名错误。只支持 SMB1 的客户端服务端照样接受，签名算法一路降到 HMAC-MD5；多通道场景下签名校验用了主通道的会话密钥，第二通道所有请求都被判成篡改；同一个 session 上两个请求并发到达，签名序列和 nonce 互相覆盖，偶发 STATUS_INVALID_SIGNATURE；加密和签名同时开启时先解密再验签，密文被改过也能通过；negotiate 响应可以被重放，攻击者拿旧响应把客户端降到无签名；签名失败后已经授予的 credit 没有回收，客户端信用耗尽后所有请求挂起；会话过期后文件句柄仍然可读写，租约没有跟着失效；重启后持久句柄恢复只看了句柄 id，没有重新校验客户端身份；关闭签名的策略按共享名匹配，大小写不同就绕过去了；目录查询结果超过 64K 输出缓冲被截断，状态码还是 STATUS_SUCCESS；并发 rename 和 open 撞在一起，句柄指向改名前的旧文件；审计日志里记了 NTLM 响应原文。smb_session_signing.py 的 SmbSigningGate 要把签名、会话和句柄绑在一起。四个硬门禁：签名校验失败必须回 STATUS_ACCESS_DENIED 并断开连接；同一 session 并发只能有一个请求通过签名校验，另一个明确拒绝；重启后持久句柄恢复必须重新绑定会话密钥；协商阶段不支持签名的客户端必须在握手时拒绝，不能运行中降级。test_smb_session_signing.py 的十五项检查目前全线告负，签名和会话两条线一起挂。

## 运行方式
```bash
python -m pytest tests -q
```
