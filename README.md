# GSB Bugfix Task
## 题面
视频巡检平台接入一批新摄像头后，轮巡画面偶尔串到别的通道，声音也断断续续。Session 头的大小写和前后空格没有归一，同一个会话被拆成两份处理；会话过期用墙上时钟判断，运维把机器时间往回调过一次，之后会话再也没过期；PLAY 请求在 SETUP 还没返回时就进来，会话状态停在半初始化，后续请求全部失败；同一条会话被两个 TCP 连接复用，两个客户端收到的交错帧互相串台；interleaved 通道号冲突时没有重新协商，RTP 和 RTCP 挤在同一个通道；Digest 认证只验 nonce 不验 nc，旧请求可以原样重放；TEARDOWN 之后 RTP 还在往旧端口发，端口一直不释放；Range 越过文件末尾时被夹到最后，而不是返回范围错误；多轨道的 RTP-Info 里序号和时间戳不成对，音画差半秒；会话数量到上限后淘汰了正在播放的那一条；服务端重启后会话编号从零重来，客户端撞上残留上下文。rtsp_session_cache.py 的 RtspSessionCache 要把会话状态迁移做成原子步骤，同一会话只允许一个控制连接，过期判定用单调时钟并支持重启后清理，通道号冲突要抛出明确异常，轨道序号和时间戳必须成对写入。RTSP 那组回归在 test_rtsp_session_cache.py 里，十五条断言眼下全部失败。

## 运行方式
```bash
python -m pytest tests -q
```
