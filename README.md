# GSB Bugfix Task
## 题面
新资料片开服那天，登录队列把玩家全得罪了。界面显示排第三位，十分钟不动，后面的人反而先进去了；拿到入场令牌后客户端崩溃，重连直接排到队尾；会员优先队列一插队，普通玩家的排队号往回跳；服务器扩容后队列没重算，容量显示满的，实际有空位；同一账号在两个区同时排队，两边都发令牌，角色数据互相覆盖；排队超时被踢出，位置还保留着，坑位一直占着；服务器重启后排队序号从头开始，最早来的人排到最后；倒计时按客户端时间算，改系统时间能跳过等待；入场令牌被重放，同一个令牌进了两条分线；跨区排队时日界一切换，整队人被清空；预计等待时间按当前速度线性算，开服十分钟后从三分钟跳到三小时；玩家在队列里充值会员，优先权立即生效，原位置却没释放，队伍里多出一个空号。login_queue_shard.py 的 LoginQueueShard 管入队、令牌、心跳、扩容和恢复。同一账号同一时间只能持有一个有效令牌，第二个请求返回 already_queued；排队序号按服务端单调时钟发，重启后从持久化游标继续，不能回绕，也不能把已经发出去的号重新分配；令牌一次性使用，重放必须拒绝并留下记录，不能放进第二条分线，令牌过期要回到原排队位置；扩容缩容后位置可以重算，但已经发出去的令牌不能失效，容量统计要把排队中和已入场分开。被踢出的玩家要能按原位置回到队列，位置保留有时间上限，超时后再释放；队列长度和实际在线人数要能对上，重连不能重复计数。开服那天的队列日志还在，先把排队号和令牌的账对清楚。

## 运行方式
```bash
python -m pytest tests -q
```
